# Game version switching via Steam depots (Fallout 4 first, game-agnostic)

## Context

Some Wabbajack lists need a specific game build. Wasteland Genesis AE needs Fallout 4 1.11.221, and preflight blocks it because 35 of its 143 game files differ. The user wants Mosaic to move the game to a chosen build, the way they already do it by hand: `steam://open/console`, look up the manifest on SteamDB, then `download_depot <app> <depot> <manifest>`. That uses the user's own licence and Valve's servers, and Mosaic holds no credentials.

Rejected: MulderLoad's patch CDN (no licence, untrusted author) and upstream's MulderLoad-under-Proton wizard. Hard rule from `wizards_qt/CLAUDE.md`: Mosaic never edits Steam's `appmanifest`.

Facts gathered by the local session (2026-10-08):
- `appmanifest_<app>.acf` → `InstalledDepots` lists exactly the user's depots (language, owned DLC) with their manifest IDs.
- SteamDB returns 403 to scripts, so manifests come from a shipped table plus user paste.
- Seed data is `zerratar/fallout4-downgrader` (GPL-3), `src/FO4Down/DepotManager.cs`: the full Fallout 4 depot→manifest table for 1.10.163. It must be credited in ATTRIBUTION.md.

## Review corrections (verified against origin/main 8d770de)

1. **`skyrim_runtime` isn't reusable as-is.** `Transition`/`FileSwap`/`apply_transition` are hpatchz-patch based (`FileSwap.forward_patch`) and refuse any app id but Skyrim's.
   - Reuse: `is_deployed()`, `_sha256`, `_free_bytes`, and the staging/`os.replace`/rollback/state-file *pattern*.
   - Don't reuse: anything else. Write a whole-file copy variant in the new module rather than calling `apply_transition`.
2. **Phase 3 depends on unpushed local work.** The Wabbajack "game version doesn't match" check and the game-file size check aren't on main (`check_game_files` only checks existence). They come from the user's local session and must land on main before Phase 3 starts.
3. **Where `download_depot` writes is unknown.** Steam normally puts it under the *Steam root's* `steamapps/content/app_<app>/depot_<depot>`, not the game's library. Don't assume a location. Phase 0 must record the real path, and the code should take it from Steam's "Depot download complete" log line, with a fallback search of the Steam root and every library's `steamapps/content`.
4. **Disk space covers three things.** A depot download is the *whole* depot at that manifest; Fallout 4's data depot is tens of GB. The backup of replaced files can be similar. So the free-space precondition must cover all three: downloads, backup, and staged copies (same filesystem as the game). The download location's filesystem may differ from the game's.
5. **Files only in the current build.** `download_depot` brings the target's files, but nothing tells Mosaic which existing files the target lacks. Steam's `depotcache/*.manifest` files are binary protobuf, which is out of scope. So keep the per-entry curated `remove` list, back those files up too, and treat "unknown extra files" as a known limit of a table entry.

## Phase 1b: local patch store (download each version once, then switch offline)

The user's question: instead of re-downloading depots on every switch, keep binary patches and apply the right one when switching profiles. Yes. This is the model `skyrim_runtime` already uses: stored hpatchz patches, with sha256 checks of each file before and after.

**How it works:**
- **First switch A→B.** Download the depots once. At that moment both versions of every changed file are on disk: the A copy (being replaced) and the B copy (from the depot). Build a patch set for each direction, then delete the downloaded depot folders and the full-copy backup.
- **Store layout.** `games/<game>/version_store/<A>__<B>/` holds a `manifest.json` plus one forward and one reverse patch per changed file. Each entry records source sha256, target sha256 and size.
- **Files that exist in only one version.** Files added in B are stored compressed: there's nothing to diff against. Files removed by B are stored compressed for the reverse direction.
- **Unchanged files** cost nothing.
- **Switching later (A↔B)** is fully offline. Each file's source hash is checked, then the patch is applied, then the target hash is checked. Everything is staged and swapped with the same `os.replace` + rollback as Phase 1.
- **Routing.** Patch sets form a graph, and a switch follows the shortest path, e.g. B→A→C. Only an edge that has never been taken needs a download.
- **Steam changing files behind Mosaic's back.** If Steam updates or verifies the game and changes files, the source hashes no longer match. The switch then refuses before touching anything, saying the game changed since the version was stored and offering a fresh download, which rebuilds the edge.

**Tool:**
- `hdiffz` builds the patches and `hpatchz` applies them. Both come from HDiffPatch.
  - Mosaic already manages `hpatchz` (`skyrim_runtime.ensure_hpatchz`).
  - Extend that so `hdiffz` is fetched the same way, from the same HDiffPatch release.
- `hdiffz` handles multi-GB files with bounded memory. `bsdiff4`, which is already a dependency, doesn't: building a diff needs memory several times the file size, so it's impractical for BA2s.

**Unknown until measured: the real saving.** A patch is only small when old and new files share content. Exes and plugins diff well. A BA2 that Bethesda re-packed or recompressed may produce a patch nearly as large as the file.
- After building a patch set, the wizard reports, per file, patch size vs. file size.
- Any file whose patch exceeds about 90% of its size is stored compressed instead of as a patch. The store is still offline and always smaller than two full copies.
- The first real 1.10.163 ↔ 1.11.221 switch gives the actual numbers.

**Disk use** is roughly the patch sizes (both directions) plus added/removed files. The Phase 1 full backup becomes temporary, kept only until the patch set has been verified by a round trip:
1. Build the patches.
2. Re-create each A file from B plus the reverse patch.
3. Hash-check the result before deleting the backup.

**Profiles:**
- Phase 3's per-profile `game_version` is what drives switching.
- On a profile switch or a deploy, when the profile needs a different version and the store has a route to it, Mosaic offers "Switch Fallout 4 to 1.11.221 (stored locally, no download)".
- This is a prompt, never automatic. A switch rewrites game files, and the game must not be deployed or running.
